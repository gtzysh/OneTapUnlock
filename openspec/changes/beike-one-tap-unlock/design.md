## Context

仓库目前几乎为空，仅有 OpenSpec 提案。用户使用 OPPO（ColorOS），已安装并登录贝壳找房，需要「点开本 App 立刻执行开门」，不再在本 App 里多点一次按钮。

开门必须经过官方贝壳找房界面；本设计用系统无障碍服务模拟点击，不直连门锁 BLE。

## Goals / Non-Goals

**Goals:**

- 从桌面点本应用图标即启动开门流程（权限已就绪时）。
- 自动打开贝壳找房，按顺序点击「我的 → 租约 → 智能门锁 → 蓝牙开门」。
- 权限未开时进入引导页，不盲点。
- 仅操作包名 `com.lianjia.beike`。
- 提供失败提示与文案设置（贝壳改版后可改点击词）。

**Non-Goals:**

- 不实现 BLE GATT / 加密开锁协议。
- 不靠近自动开、不定时开、不后台静默开。
- 不覆盖 iOS。
- 不修改贝壳找房本身。

## Decisions

1. **触发方式：启动器图标 = 开门**  
   `MainActivity` 在冷启动 `onCreate` 与热启动 `onNewIntent` 中启动流程。从最近任务恢复（`FLAG_ACTIVITY_LAUNCHED_FROM_HISTORY`）不重复开门，避免误触。  
   备选：主界面再放「开门」按钮——用户已明确不要这步，故不用。

2. **自动化：AccessibilityService，包名白名单**  
   只接收贝壳窗口事件，用 `findAccessibilityNodeInfosByText` 点可点击节点或其可点击父节点。  
   备选：坐标连点——分辨率一变就失效，不用。

3. **状态机在本应用进程内**  
   `UnlockCoordinator` 持有步骤与超时；Service 在窗口变化时尝试当前步骤。每步超时约 12 秒，总超时约 45 秒。  
   成功后留在贝壳页面（用户看开锁结果），本应用 Toast 提示「已点击蓝牙开门」。

4. **设置入口与启动器分离**  
   主图标只开门。长按图标提供「设置」快捷方式；引导页/失败页也可进设置。避免每次开门先看到设置页。

5. **技术栈：单模块 Android Kotlin + AndroidX，无第三方 SDK**  
   minSdk 26，targetSdk 34。中文注释按项目约定 `// 【xxx】`。

6. **OPPO**  
   文档写明：无障碍、后台弹出界面、自启动、耗电不冻结。应用内引导用系统 `ACTION_ACCESSIBILITY_SETTINGS` 跳转。

## Risks / Trade-offs

- [贝壳改版/H5 租约页节点无文字] → 设置里可改关键词；超时后提示「请手动点一次并反馈文案」。
- [启动弹窗（更新、隐私、定位）挡住] → 不自动点「同意」；超时失败，提示先关掉弹窗再点本图标。
- [无障碍权限被 ColorOS 杀掉] → 引导耗电白名单；失败时检测服务是否仍连接。
- [误开锁] → 必须用户点图标；不从最近任务自动跑；不做地理围栏。
- [无障碍能力被滥用] → 服务配置 `packageNames` 仅贝壳；不读其它应用内容。

## Migration Plan

- 新工程，无旧数据。用户用 Android Studio 编译安装即可。
- 卸载即关闭无障碍服务。无需回滚脚本。
